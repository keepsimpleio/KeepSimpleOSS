# Library release incident review

Scope: the release and fix work reported during this conversation and the project history dated 2026-09-07. Machine evidence uses UTC. This is an incident inventory, not a claim that every visual state was inspected in a browser.

## Main finding

A frontend build was repeatedly treated as evidence that a feature worked across the deployed system. Library behavior also depends on CMS code, database fields, role permissions, account feature flags and the network used to fetch covers. Those dependencies were not kept in one release checklist. The production Favorites visibility failure was a missed CMS deployment, not a new frontend defect.

A second failure was reporting a wider conclusion than the evidence supported. A test account was used to stand in for Wolf's account. HTTP 200 was used to stand in for persisted data. Staging and production were assumed to behave alike despite different permissions and deployed CMS versions. These substitutions must stop.

- Private evidence: docs/library-ai-shelf-backend, docs/release-staging and docs/prod-books-to-dev. These contain journals and snapshots and must remain ignored. Credentials must never enter reports.
- Conversation screenshots130-144 cover the reported UI and production failures. Earlier raw history confirms favorite loss after editing, hover/focus and notes issues.
- No production data loss was observed. No production owner API roundtrip was performed by the final repair probe. Wolf subsequently reported that the feature appeared to work; this is user acceptance, not an agent-run test.

## Remaining work, not silently included in this audit

- Staging CMS still lacks favorites_visibility. The new target contract intentionally fails there. Reconcile CMS at the next authorized staging release before claiming parity.
- Public directory search still uses a user relation filter; the username navigation workaround scans pages. Add a bounded public lookup/search endpoint in CMS instead of exposing user-account access. Current production has three libraries; this limits current cost, not future risk.
- Duplicate Sidebar copied-reset timer and RecommendedBookCard module counter remain cleanup items. They were not fixed by answering review comments.
- Review Docker cache/runtime size separately; stage/prod runtime configuration is required before shared image promotion.
- Visual tooltip layering, modal focus return and motion still require user acceptance. Automated source checks cannot certify appearance.
- A production backup was created, but no restore drill was performed. Do not imply recoverability was exercised.

## New evidence standard

A release can have passing build, API, data and visual checks independently. Missing evidence stays BLOCKED or NOT TESTED. No summary may turn those states into an overall “everything passed.” No rule can promise zero future defects; the checks below turn today's known omissions into explicit failures.
